# 実装比較メモ

このメモは、同じハッシュ確認ツールを複数の実装で作成したときの違いを記録するためのものです。

業務制約の中で作成した PowerShell 版も比較対象に含め、制約がある状態とない状態で設計・実装・配布の考え方がどう変わるかを整理します。

## 実装順

1. PowerShell（業務制約版・既存実装）
2. Python
3. Go
4. C#/.NET
5. Rust

## PowerShell（業務制約版）

- 目的: 実務上の制約内で、Windows 標準機能を使ってハッシュ確認を行う
- 強み: Windows 環境に標準で近く、追加インストールなしで使いやすい
- 見せどころ: `Get-FileHash`、`.bat` からの実行、利用者向けメッセージ、手順化
- 注意点: 業務制約に合わせた作りのため、共通仕様準拠の基準実装とは位置づけが異なる

### 業務制約時のメリット

- 利用者が普段使う Windows 環境に合わせやすい
- 追加ランタイムや外部ライブラリを入れずに運用しやすい
- `.bat` をダブルクリックする運用に寄せられる
- セキュリティや社内ルール上、導入しやすい形にしやすい
- 実務で必要な範囲に絞るため、説明や手順を固定しやすい

### 業務制約時のデメリット

- 汎用的な CLI 設計やテスト自動化を入れにくい
- エラー処理、終了コード、入力検証を言語間で揃えにくい
- 他 OS への展開や単一バイナリ配布には向かない
- 実装の目的が「業務で動くこと」に寄るため、学習・比較用の構造化とは相性が弱い
- 制約に合わせた判断が多く、ポートフォリオでは設計意図の補足が必要になる

### 制約なし実装と比べた見方

制約なしの多言語実装では、共通仕様、テスト、終了コード、CLI 引数、入力検証を揃えやすくなります。一方で、利用者の環境に合わせた簡単さや導入しやすさは、業務制約版の PowerShell の方が説明しやすいです。

そのため、このリポジトリでは PowerShell 版を「実務制約内での実装例」、Python 以降を「共通仕様に沿った比較・学習用実装」として扱います。

## Python

- 目的: 共通仕様を最初に固めるための基準実装
- 強み: 標準ライブラリだけでファイル I/O、CLI、ハッシュ計算、テストを書きやすい
- 見せどころ: 仕様分離、入力検証、終了コード、テスト容易性
- 注意点: 配布時は Python 実行環境、または exe 化の検討が必要

## Go

- 目的: 単一バイナリ配布と静的型付けの比較
- 強み: 配布しやすく、CLI ツールとの相性がよい
- 見せどころ: `crypto/md5`、`crypto/sha256`、明示的なエラー処理、クロスコンパイル

## C#/.NET

- 目的: Windows 業務ツール寄りの実装比較
- 強み: Windows 環境、GUI 化、配布形式との相性がよい
- 見せどころ: `System.Security.Cryptography`、CLI/GUI 展開、例外処理

## Rust

- 目的: 堅牢性、型安全性、配布性の比較
- 強み: 単一バイナリ、堅牢なエラー型、性能
- 見せどころ: 所有権、Result ベースのエラー処理、依存関係の選定
